# 业务逻辑说明 — py-genai-graph

## 1. 图谱空间模型
- 图谱创建必须携带有效 `space_id`；空间删除前校验名下图谱，非空 400。
- 存量无归属图谱自动归入「默认空间」（mapper 启动迁移）。

## 2. 双存储后端
- `db_type=sqlite`：graph_mapper 内置 SQLite 表读写。
- `db_type=neo4j`：按图谱 `db_config`（uri/用户/密码）通过 Neo4j HTTP API 真实读写。
- 业务层按图谱配置路由到对应 mapper 方法，接口行为一致。

## 3. 实体类型 / 节点 / 关系
- 实体类型携带 `props_schema`（JSON 数组，定义属性名与类型）。
- 节点必须归属实体类型（entity_id）并带名称；属性 props 为 JSON 对象。
- 关系 = source_id → target_id + rel_type；删除节点级联清理关联关系。

## 4. 邻域查询
`GET /api/graphs/{gid}/neighborhood?nids=id1,id2&depth=1..7`：从**多个起点节点**按关系无向展开 1~7 级子图
（返回 nodes + edges），兼容旧 `nid` 单节点参数；sqlite/neo4j 统一本地 BFS，避免 Neo4j Cypher 结果丢弃问题。
前端图视图「多选节点下拉 + 级数 + 查询邻域按钮」使用。

## 4.5 数据关系视图（族群放射布局）
- 前端 `Graph.vue` 图视图为**圆形节点 + 分散/分群/分族群**放射布局（参考知识图谱可视化范式）：
  - **分群维度**：优先取节点 `props.辈分`（族谱按 嘉/运/乾/坤/增/长 六代分族），其次 `props.实体类型` 或实体类型名。
  - **族群摆放**：各族群中心按黄金角螺旋散布在画布上（2600×1800 逻辑坐标），彼此留白。
  - **放射结构**：每族选度数最高节点作 hub（大圆 r=42）居中，其余成员按同心环（环距 165）放射分布。
  - **着色**：8 色调色板按族群区分；边为圆心到圆心连线 + 箭头；节点名白字在圆内、状态/属性在圆下小字。
- 鼠标悬浮节点/边弹出提示框：节点显示名称/类型/ID + 属性键值（≤8 项），关系显示类型 + 起点→终点 + 关系属性。
- 缩放控件 ➕/➖/⌂ 以画布中心缩放；点击节点/边下方详情面板展示属性/状态/版本与增删改操作。

## 5. 版本管理（版本号 + 自动快照 + 恢复）
- **版本号**：`tb_graph.version`（默认 `v1`），每次写操作（图谱/空间/实体/节点/关系增删改、版本恢复）由 `bump_version()` 递增 `v1→v2→...`；前端图视图标题旁以标签展示。
- **版本快照**：节点/关系的增删改自动写入 `tb_graph_version`（记录操作类型与数据）；`save_version()` 统一埋点，内部同时递增版本号并写审计日志。
- `versions` 列表 / `{vid}/detail` 详情 / `{vid}/restore` 一键恢复到历史版本（恢复前自动存当前态）。

## 6. 跨模块图谱来源与编辑权限
- `tb_graph.source_module` 标识图谱来源：`graph`=知识图谱模块创建（可编辑，默认）；`ontology`=本体图谱模块创建。
- 两个模块共享同一份图谱数据（本体模块只读引用 `py-genai-graph/graph.db`），因此**相互可见**：
  本体创建的图谱出现在知识图谱列表，鼠标悬停来源标「只读」；本模块图谱也可被本体模块作为 `graph-ref` 数据源展示。
- 非本模块来源的图谱：**仅可查看，不可编辑**。读接口（列表/节点/关系/邻域/版本）正常；
  所有写接口（图谱/实体/节点/关系增删改、版本恢复）经 service 层 `_require_editable()` 统一守卫，
  返回 `HTTP 403 {detail: "无编辑权限"}`。前端根据列表返回的 `editable=false` 隐藏全部写入口。
- 存量迁移：`migrate_source_module()` 把「万家家族族谱」标记为 `ontology`（幂等）。
- 本体模块可通过 `POST /api/onto/graphs` 创建 `ontology` 来源图谱，创建即标记来源，无需人工改库。

## 7. 审计日志（操作记录）
- `tb_audit_log(module, target_type, target_id, target_name, op, detail, operator, created_at)`：记录图谱/空间/实体/节点/关系等全部写操作，`op` 如 `create_graph/update_node/delete_edge/restore`。
- **操作人**：纯 ASGI 中间件 `AuditContextMiddleware`（在 `main.py` 挂载）从请求头 `Authorization` 的 JWT payload 解析 `sub`，写入 contextvar；由 mapper.audit() 读取记录（无 token 时为 `system`）。
- 版本快照写入（`save_version`）统一连带记录审计；`graph_update`/`graph_delete`/空间操作单独埋点（即使无版本快照也留痕）。
- 查询接口 `GET /api/graphs/audit?gid=&limit=`（gid 省略=本模块全部）；前端 Graph.vue「审计日志」tab 按时间倒序展示，支持刷新。

## 8. 网关接入
`common/gateway_report.py` 单例：`init(settings)` 注册+心跳，`install(app)` 挂载请求采集，
lifespan 退出时 `stop()` 优雅下线。
