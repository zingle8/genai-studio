# 业务逻辑说明 — py-genai-ontology

## 1. 本体空间模型
- 本体创建/更新必须携带有效 `space_id`（`_require_space` 校验，否则 400）。
- mapper 导入时 `migrate_ensure_space()`：保证至少存在「默认空间」，存量无归属本体自动归入。
- 空间删除前校验 `tb_ontology.space_id`，非空 400（对齐知识库空间行为）。

## 2. 类与关系规则约束
- **类**：同一本体下类名唯一（新增与表单编辑均校验，编辑排除自身 id）。
- **关系规则**：`本体 + 关系名 + 主语类 + 宾语类` 四元组唯一；`cardinality ∈ {one, many}`；表单编辑走 `PUT /api/onto/rels/{rid}`。
- **映射**：本体类型 ↔ 物理类型，kind ∈ {node, edge}，用于视图投影。

## 3. 导入导出（双格式 DSL）
- `POST /api/onto/import`：按 `format` 分发 `parse_ttl` / `parse_yaml`；解析失败抛 ValueError → 400；
  同名类/同四元组关系跳过（幂等导入），返回 `{classes, rels, issues}`（issues 为导入后一致性检查结果）。
- `GET /api/onto/{oid}/export?format=ttl|yaml`：从库中读类与关系，序列化为对应格式文本。
- 解析器位于 `common/onto_parser.py`，与业务解耦，可独立测试。

## 4. 一致性检查
`common/onto_checker.check_ontology(oid)`：基于库内类/关系规则做规则校验（如孤立类、关系端点类不存在等），
返回 issue 列表；导入接口自动附带执行。

## 5. 图数据源与本体视图投影
- `GET /api/onto/datasources`：首次调用自动注册「内置示例·公司数据」数据源。
- `GET /api/onto/graph-data?ds=`：builtin-demo 返回 DEMO_DATA；其他类型返回占位（待接入 Neo4j）。
- `GET /api/onto/{oid}/view-graph`：读取本体映射，按 `kind=node/edge` 过滤物理数据的类型，实现本体视角投影。

## 5.5 数据关系图（族群放射布局）
- 本体页「数据关系图」tab 把数据源实例（物理数据 / 本体视角投影）画成关系节点图，兼容 `graph-ref`（props JSON 字符串、source_id/target_id）与 `builtin-demo`（props 对象、from/to）。
- 布局与知识图谱一致：**圆形节点 + 分散/分群/分族群放射**——分群维度优先 `props.辈分`/`props.实体类型`（否则节点 `type`）；族群中心黄金角螺旋散布（3000×2000 画布），每族度数最高节点作 hub（大圆 r=46）居中，其余同心环（环距 170）放射。
- 8 色按族群区分；名字白字在圆内、状态在圆下小字；边为圆心连线 + 箭头。多节点下拉 + 1~7 级邻域查询；悬浮提示节点属性 / 关系起止与属性；下方详情面板展示完整属性。
- 数据源随本体自动匹配（如 万家家族族谱 → 万家家族族谱·实例数据 graph-ref），工具条标注来源图谱与「数据实例」标识，避免与本体定义（类/规则）混淆。

## 6. 版本号 + 版本快照（对齐图谱模块）
- **版本号**：`tb_ontology.version`（默认 `v1`），每次写操作由 `bump_version()` 递增 `v1→v2→...`；前端本体选中卡展示。
- **版本快照**：`tb_onto_version(ontology_id, version_no, op, note, snapshot, created_at)`，快照含 `ontology/classes/rels/mappings` 全量定义。
- 本体/类/关系/映射的每次写操作（含导入）自动调用 `db.save_version(oid, op, note)` 递增存版，内部同时递增版本号并写审计日志。
- 恢复流程：当前态先存 `pre_restore` 版 → 按目标快照原 ID 回填类/关系/映射 → 再存 `restore` 版。
- 前端「版本」tab 可查看列表、快照内容与一键恢复；节点选中卡的「最近变更」也取自版本列表。

## 7. 图数据源类型
- `builtin-demo`：内置示例公司数据。
- `graph-ref`：跨模块引用图谱实例的 `graph.db`（`config.graphId` 指定图谱 id），读取节点（按实体类型映射 type）与边（按 rel_type 映射 type），可在「数据映射」tab 直接查看实例并做本体视角投影。万家家族族谱即通过此方式绑定图谱 id=9。
- 其他类型：占位待接入 Neo4j。

## 8. 创建图谱与跨模块编辑权限
- `POST /api/onto/graphs`：本体模块创建图谱，数据落在 `py-genai-graph/graph.db` 的 `tb_graph`，
  `source_module=ontology`；`GET /api/onto/graph-spaces` 提供可选归属空间（取自图谱模块空间表）。
- 来源语义：本体创建的图谱在知识图谱模块**可见但不可编辑**；知识图谱模块所有写接口统一返回 403「无编辑权限」。
  本模块对本体自身定义（本体/类/关系/映射）的编辑不受影响。
- 前端本体页「＋ 新建图谱」入口创建后，可在「数据映射」tab 将其作为 `graph-ref` 数据源查看实例。

## 9. 审计日志（操作记录）
- `tb_audit_log(module, target_type, target_id, target_name, op, detail, operator, created_at)`：记录本体/空间/类/关系/映射/数据源/创建图谱等写操作，`op` 如 `create_class/update_rel/delete_mapping/create_graph`。
- **操作人**：纯 ASGI 中间件 `AuditContextMiddleware`（在 `main.py` 挂载）从请求头 `Authorization` 的 JWT payload 解析 `sub`，写入 contextvar；由 mapper.audit() 记录（无 token 时为 `system`）。
- 版本快照写入（`save_version`）统一连带记录审计；空间操作、数据源新增、本体创建图谱单独埋点。
- 查询接口 `GET /api/onto/audit?oid=&limit=`（oid 省略=本模块全部）；前端 Onto.vue「审计日志」tab 按时间倒序展示，支持刷新。

## 10. 网关接入
`common/gateway_report.py` 单例：`init(settings)` 注册+心跳，`install(app)` 挂载 FastAPI 请求采集，
lifespan 退出时 `stop()` 优雅下线（冲刷日志队列 + 注销）。
