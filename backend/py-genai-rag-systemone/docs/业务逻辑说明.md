# SystemOne 判断模型服务（laya + nanojev） — 业务逻辑说明

1. laya（MLX）：单 state 决策；batch 串行求解（MLX 并发会互相打断）；route 经 Router 按语言选槽位（英文权重缺失回退多语言）
2. nanojev（torch）：states[] 展开全部 state×question 候选路径合并一次前向（autocast bf16，待接入网络结构）
3. service 层把两引擎答案统一为 AnswerResult（selected/probability/value/score/distribution，noul↔boolean 字段名归一）
4. 异常翻译：ModelUnavailable/EngineNotLoadedError → 503 / ValueError → 400
5. 暂不要求跑通：依赖缺失时服务可启动，/health 报告各引擎 ready 状态

## 公共 loading 机制

引擎均继承 `backend/py-genai-loadmodel/loadmodel/base_engine.py` 的 `BaseModelEngine`：

- `load()`：幂等（重复调用直接返回）、加锁、计时（load_seconds）、异常降级（依赖/权重缺失仅记录 load_error，不阻塞服务启动）
- `inference_lock()`：推理互斥（模型推理串行执行）
- `describe()`：统一状态字段（model/backend/ready/device/load_seconds/load_error），health 与 config 接口复用
- `pick_device()`：auto → cuda / mps / cpu 自动选择
