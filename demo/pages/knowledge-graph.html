图谱开放能力

                  
通过 MCP Server / REST API / SDK 三种方式访问图谱与本体，均使用同一把 API Key 鉴权

                

                Bearer $AI_STUDIO_API_KEY
              

              

                

                  

                    
MCP Server推荐

                    
以 MCP 工具方式暴露图谱检索与本体校验能力，Claude / Cursor 等客户端可直接接入，无需自行编写图查询语言。

                  

                  

                    
REST API（curl）

                    
标准 HTTP 接口，适用于后端服务、数据管道与定时任务；支持分页检索、构建任务触发与本体约束校验。

                  

                  

                    
Python / Java SDK

                    
封装鉴权、重试与分页逻辑，适合在应用内做 GraphRAG 问答、实体写入与批量校验。

                  

                

              

            


            

              

                

                  
MCP 工具列表

                  
MCP Server 暴露的图谱 / 本体工具，客户端通过 tools/call 调用

                

              

              

                

                  

                    
                      
工具说明主要入参类型

                    
                    
                      
kg.search_entities混合检索实体（向量 + 关键词）query, top_k, entity_types[]只读

                      
kg.expand_neighborsN 跳邻接实体扩展，用于 GraphRAG 上下文entity_id, hops, rel_types[]只读

                      
kg.query_cypher执行只读 Cypher 查询（超时自动中断）cypher, limit, timeout_ms只读

                      
kg.upsert_entities实体 / 关系批量写入（幂等，按主键合并）graph_key, entities[], relations[]写入

                      
kg.build_job查询构建任务进度 / 触发增量与全量构建graph_key, action(query|trigger)写入

                      
onto.get_schema获取本体 Schema：实体 / 关系 / 属性与约束ontology_key, version只读

                      
onto.validate按约束 YAML 校验实体数据（必填 / 正则 / 枚举 / 范围）ontology_key, entity, payload只读

                    
                  

                

              

            


            

              

                

                  
curl 接口列表

                  
REST API v1 · 基础地址 https://api.example.com/v1

                

              

              

                

                  

                    
                      
方法路径说明类型

                    
                    
                      
POST/graphs/{graph_key}/query执行图查询（Cypher / GQL）只读

                      
GET/graphs/{graph_key}/entities/{id}实体详情与一跳邻接关系只读

                      
POST/graphs/{graph_key}/entities:search实体检索，支持分页与类型过滤只读

                      
POST/graphs/{graph_key}/build-jobs触发增量 / 全量构建任务写入

                      
GET/ontologies/{ontology_key}/schema本体 Schema 与版本信息只读

                      
POST/ontologies/{ontology_key}:validate按本体约束校验实体数据只读

                      
GET/ontologies/{ontology_key}/changes本体变更申请列表与审核状态只读

                    
                  

                

              

            


            

              

                

                  
使用案例

                  
复制即可运行，替换 API Key 与图谱标识

                

              

              

                

                  
案例 1 · MCP 客户端检索实体复制

                  
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "kg.search_entities",
    "arguments": {
      "query": "iPhone 15 Pro 的运行内存",
      "top_k": 10,
      "entity_types": ["商品", "属性"]
    }
  }
}

                


                

                  
案例 2 · curl 执行 Cypher 查询复制

                  
curl -X POST https://api.example.com/v1/graphs/kg_ecommerce/query \
  -H "Authorization: Bearer $AI_STUDIO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "language": "cypher",
    "statement": "MATCH (p:商品)-[:belongs_to]->(c:类目 {name: \'手机数码\'}) RETURN p.name, p.price LIMIT 20"
  }'

                


                

                  
案例 3 · curl 按本体约束校验实体数据复制

                  
curl -X POST https://api.example.com/v1/ontologies/ontology_ecommerce:validate \
  -H "Authorization: Bearer $AI_STUDIO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "entity": "商品",
    "payload": {
      "sku_id": "SKU00012345",
      "name": "iPhone 15 Pro",
      "price": 7999.00,
      "level": "旗舰"
    }
  }'

# 响应
{
  "valid": false,
  "errors": [
    { "field": "sku_id", "rule": "pattern ^SKU[0-9]{8,12}$", "msg": "长度不足 8 位" }
  ],
  "warnings": [{ "field": "level", "msg": "枚举值建议收敛为：入门 | 中端 | 旗舰" }]
}

                


                

                  
案例 4 · Python SDK 做 GraphRAG 问答（含图谱路径溯源）复制

                  
import os
from ai_studio import GraphRAG

client = GraphRAG(api_key=os.environ["AI_STUDIO_API_KEY"])

ans = client.ask(
    question="近一个月销量最高的手机分别属于哪些品牌？",
    graph_key="kg_ecommerce",
    hops=2,          # 邻接扩展跳数
    top_k=8,         # 召回实体数
    with_path=True   # 返回用于溯源的图谱路径
)

print(ans.answer)
for path in ans.paths:
    print(" → ".join(path))

# 输出示例
# 近一个月销量 Top3 为 iPhone 15 Pro、小米 14 Ultra、华为 Mate 60，分别属于 Apple、小米、华为。
# iPhone 15 Pro → belongs_to → 手机数码 → produced_by → Apple

                


                

                  
案例 5 · 触发增量构建并轮询进度复制

                  
JOB=$(curl -s -X POST https://api.example.com/v1/graphs/kg_ecommerce/build-jobs \
  -H "Authorization: Bearer $AI_STUDIO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"mode": "incremental", "sources": ["product_doc", "review_doc"]}' | jq -r .job_id)

curl "https://api.example.com/v1/graphs/kg_ecommerce/build-jobs/$JOB" \
  -H "Authorization: Bearer $AI_STUDIO_API_KEY"

# 响应：{ "job_id": "job_9c21", "status": "running", "progress": 78, "eta": "约 4 分钟" }

                

              

            


            

              

                

                  
图谱使用步骤教程

                  
从本体定义到线上检索的完整流程

                

              

              

                

                  1
                  
定义本体（本体图谱Onto）新建本体图谱 → 用「状态编辑图 / 属性画布 / YAML / Chat」四种方式定义实体、关系与属性约束 → 在「本体图谱审核」中通过变更 → 发布版本并生成约束 YAML。

                

                

                  2
                  
构建图谱（知识图谱Graph）在「知识图谱编辑」绑定本体 Schema 与数据源 → 选择抽取方式（LLM 抽取 / 规则抽取 / 专家标注）→ 在「构建任务」中触发增量或全量构建 → 观察进度与日志。

                

                

                  3
                  
配置检索策略选择目标图谱 → 设置召回方式（GraphRAG 邻接扩展 hops、向量召回、关键词召回）→ 绑定知识库与重排模型 → 在「知识图谱查询」中用 Cypher / 自然语言验证召回效果。

                

                

                  4
                  
接入应用创建 API Key 并授予只读或写入权限 → MCP 客户端配置 Server 地址，或后端直接调用 REST API / SDK → 用 kg.search_entities、kg.expand_neighbors 拼装上下文。

                

                

                  5
                  
运维与迭代监控「构建任务」成功率与耗时 → 处理本体变更申请并回归校验（onto.validate）→ 发布新版本后灰度切换 graph_key → 定期用「实体与关系浏览」抽查数据质量。
